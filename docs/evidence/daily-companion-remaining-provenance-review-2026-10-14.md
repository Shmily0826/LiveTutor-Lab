## Shared guards must be retained

`entry_tutor_context_support._build_learning_context:639-690` uses captured session history, course-filtered previous history, current question, recent events, language and preferences. `_record_tutor_result:838-884` refuses to put a different request session's late result into the new live seed/current question/evaluation/summary. `_finalize_tutor_call:919-954` writes history into the request session. These already prevent some cross-course live-state contamination; they do not reject an old result returned to Native, and the material hash check/lock-coordinated SQL append is conditional on a nonempty `_material_context`. `material_context_current(None)` deliberately permits legacy callers.

Question generation has an additional real scope fence for targeted practice: `_generate_question_payload:523-538,609-634`, plus cached selection revision checks at `190-200`. Course change resets active practice scope and increments revision; session start clears current question except the explicit same-course resume case (`__init__.py:811-826`). Same-course restart alone need not change practice scope revision. Therefore targeted scope safety should not be claimed as a general course/session/image fence.

Answer tracking already writes question/answer/mastery evidence through the existing Store/tracker using captured context (`entry_tutor_context_support:1113-1154`). Changing material must not delete a committed old-session answer or rebuild memory. A saved question is an immutable question artifact: grading its IDs does not automatically mean grading the newly selected image. Product policy must distinguish “answer this held question” from “grade against current picture.”

## Default-off narration and host limitation

The current desktop builder copies base plugin then overlay (`scripts/neko_desktop_tutor_host.py:222-248`) and sets the plugin communication manifest default to `enabled = false`. The model defaults themselves are `enabled=True, silent_mode=True` (`payload/study_companion/models.py:275-285`); startup only creates EventBus for enabled AND nonsilent (`__init__.py:338-345`). Thus the isolated daily path defaults off, but an explicitly changed configuration is not universally off.

Base EventBus queues asynchronously and builds push payloads without provenance metadata (`_event_bus.py:142-181,298-342`). `session_summarized` uses `read`; general/solution use `respond`; incorrect/partial answer feedback can be promoted to `respond` with cooldown (`35-64,518-540`). These are push-message role behavior requests. External TTS remains blocked by the daily host's provider/worker policy (`neko_desktop_tutor_host.py:54-62,120,1019-1031`), while Native PCM transport is permitted. Do not label a scheduled push as submitted playback, finished cancellation, or device speech.

Current built host Core accepts material output ownership only for trusted `plugin:study_companion` **`study_explain`** calls and valid nondegraded string `reply` (`benchmarks/raw/neko-product-host/main_logic/core/tool_calling.py:142-205`). Merely adding `_study_material_binding` to quiz/answer/summary producer output would not activate its consumer; quiz's spoken field is `question`, not `reply`. Other independent Native outputs can also supersede the last explain owner's speech without having their own material provenance. This report does not prove that such a collision occurred in replacement13.

## Smallest reuse candidates

1. For picture-grounded quiz, capture exact role and full existing `material_context` + image/OCR together under the state lock before the first await; pass image and context into `_generate_question_payload`, recheck at context/model/finalizer/return as explain does. Ordinary explicit text/adaptive topic quiz should use course/session subset, not claim it inspected a stored picture. Preserve targeted scope fences. Store source context in existing private question payload/history metadata, not another memory system.
2. For answer, preserve identity reservation, duplicate/cache recovery and course-scoped mastery. Carry the held question's recorded origin and captured request course/session through evaluation. Check current request scope before finalizer/Native return. If the held question is immutable text, image-only replacement should not falsely invalidate it; if current-image evidence is requested, snapshot/check that material separately. Do not silently relabel an old question as the new image.
3. For summary, use captured course/session subset, verify it after ensure/context/model and before return; summarize immutable scoped history without a picture claim. This also closes the old-history/new-course context window.
4. Reuse `bind_material_output` only for successful, current output, at each Native wrapper's final return. Extend Core's exact trusted tool allowlist and per-tool spoken-field validation together; retain connection/scope/provider fences and remove host-only metadata from model-facing output. Binding producers alone is insufficient.
5. If separate narration is enabled later, carry the request binding/target in the existing event payload and push metadata; reject stale material when draining the queue and at host output admission. Do not route cancellation through EventBus cooldown/off switches. `session_summarized` currently reads live summary seed after awaits (`entry_communication_tutor_events.py:165-200`), so use the request's captured seed/context rather than enriching an old summary from the new course. Native default-off delivery can be improved first; do not enable another narration path merely to claim coverage.
