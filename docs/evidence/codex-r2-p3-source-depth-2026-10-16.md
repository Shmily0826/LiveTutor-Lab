# P3：源码两句话与 Native 参数格式

## 定位

上一轮第2步，任务库中的教师原答就只有一句；读取范围15–24，不含26。Native把这一句进一步概括。不能将缺第二句全部归因于Native relay。

本轮真实文字SDK给出18–29完整范围、原句“两句话”，教师返回两句，但第二句仅说异常交给调用方，没有说明后续解析不执行。补充通用教师指令：解释guard/error处理时追踪后续已展示语句是否执行、引用实际行；假设响应体的解析结果应以条件表达，不能猜“大概率失败”。工具说明要求有界窗口包含guard后的语句。relay改为逐句传递，不添加过渡句，不硬编码weather/404答案。

## 新库参数格式

没有预先源码定位的Native场a仍拒绝范围，形状list[1]:str。加了受限的JSON对象字符串解码后，场b的内容无关日志明确出现 `decoded request shape=list[1]:['str:json_object']`，证实本次角色实际把对象序列化成字符串。解码仍经过原有字段、窗口、授权过滤；格式错误或未知字段会拒绝，不能悄悄退回旧窗口。

这解释了本轮新库首场参数拒绝；不证明所有历史空回合都有这个原因，历史没有记录字符串内容。
