Status: read-only design review. No implementation, tests, model, host, provider, device, DB, ledger or online operation was performed. Main owns implementation and acceptance. ## Bounded design judgment

The proposed route can preserve the existing tool owner **without a cross-scope transaction**, provided its callback is synchronous and every specified predicate is checked before any scope advancement. A redundant pure grading request need not become a new user tool scope when a still-current local claim already has that explicit answer and the exact completed local input. This is suppression of a redundant request, not a new authorization, provider utterance identity or merging of transcripts.

The double guard against new positive DSP input is supported by actual source. Deployed `_transport.py:1644` calls `_capture_study_grade_pin` before the first await; after its first valid ASR consumed the old pin, another positive frame establishes a non-None pin immediately. At lines 1680–1692, admitted positive speech increments `_voice_handoff_input_sequence` synchronously before the shared async admission boundary. Even an early-return path that only establishes a pin must make the filter fail. The callback therefore must require **both** no new pin and unchanged original frame sequence, rather than treat either as a sufficient identity. These counters identify admitted local input changes, not a provider utterance.

Current `NativePhraseUplink` retains the actual `waiting` sequence after successful writes (helper line 228), clears it for a new positive input sequence (line 117), and clears waiting/snapshot on retire (line 51). Its source report is the actual `_native_phrase_last_delivery` object, assigned before writing and marked `written_waiting_provider_boundary` only after successful full output. Capturing that exact object together with current driver/snapshot, waiting sequence and complete counts can support this **local-input-only** eligibility proof. A copied dict with matching numbers, a previous successful report, or local UUID cannot replace the exact binding.

## Required implementation checks and counterexamples

- The callback must be Core-bound to the active source, receive the actual message provider/generation, and compare source/ws/generation/token/scope plus Core activation/socket and original input sequence. Check the original claim with its current owner; never recapture the latest owner, increment/decrement scope, fake `already_scoped`, or shield a retired tool task to make it eligible. Any missing authority or exception should fall through to normal ASR scope handling.
- Capture `sealed_phrase` only when a live actual driver is current, its waiting sequence equals the original receipt sequence, and its exact last-delivery object reports full writes for that original connection. On the tail, require that same driver, snapshot, delivery object and waiting sequence, with no new buffer/retire/replay transition capable of substituting a later input. The declared requirement `source._study_grade_pin is None` is essential even when frame count is unchanged.
- The callback must be **synchronous**, contain no await or asynchronous DB work, and transport may skip normal scope advancement only when the result **is True**. A truthy coroutine, object, `1`, missing callback or callback exception must not swallow ASR. A direct bounded readonly pin lookup may fail closed; it must never initialize/recover a session, adopt a replacement question, or read a different runtime store. Compare four exact original IDs; do not adopt the current DB values as new claim authority.
- Check task retirement as well as failure: cancelled, **cancellation requested but not yet done** (`cancelling() > 0`), done-with-exception or done-without-valid-result must refuse. Do not invoke `.exception()` on a cancelled task without guarding it. Eligibility must end when the old claim/source is released, reconnected, retired or expires. Restrict the extra tail handling to a bounded count/deadline; it is not a way to keep an old owner alive indefinitely.
- Use anchored full-string matching after a narrowly specified copy-only normalization of Chinese intra-character whitespace and terminal punctuation. Only the reviewed pure requests (e.g. `请评分`, `点评分`, `请打分`, `评分`, `打分`) qualify. Do not use substring matching, quote stripping that turns a quoted instruction into authorization, negation deletion, broad punctuation-word removal, or an LLM paraphrase. Preserve the raw provider ASR in its original trace, add a separate counts-only consumed-tail diagnostic, and never append that tail to the original answer or overwrite the formal input text.
- Test reject cases such as `不要评分`, `别打分`, `评分前先等一下`, `请评分但答案改为REZ`, `不是WEX，是REZ`, quoted `“评分”`, other/new question, a bare grading request with no eligible claim, unknown language/fragment, wrong source/old socket, no waiting marker, replaced driver, equal-but-copied delivery object, incomplete/failed write, foreign connection, changed pin/course/session/attempt, and disabled feature. A nonqualifying tail must execute **unchanged normal scope retirement**, including cancellation of old tools; it must not merely be hidden from teaching text.
- New positive PCM before callback, at an SDK wait, while a control/frame lock is held, and during reconnect must win. Test the synchronous pin-only early return and frame-sequence-only change independently. Also test new input after the callback returns: the pending claim still needs its existing before/after-await owner checks, so a successful tail filter is never a permanent lease. Ordinary mode and non-phrase/raw paths must keep exact method/behavior when opt-in is off or no sealed receipt exists.
- Competing provider `study_answer` calls must join the actual current local claim through its existing exact mechanism, with one formal write, one controlled relay, and honest timeout/failure. The filter cannot bypass the join's new-owner checks or let a stale provider call grade again. Late old-provider messages after connection retirement must retain their existing rejection.

These are specific required negative fixtures for Main's actual Core/Omni implementation; they were not run by this review. The current source has no tail callback yet, so these checks are not claimed to exist.

## Declaration admission and the remaining causal limit

Adding declaration-only answer intent is a deliberate product-policy change from the current helper's judge-required rule. If implemented, keep it narrower than existing broad personal-answer recognition: explicit target plus an actual declaration such as “我的答案是/为…” (and an explicitly reviewed English equivalent), with existing refusal/hypothetical/quotation controls. Do not broaden “我认为 / I think” merely because a current question happens to exist. Evaluated attempts remain explicit corrections, never an ordinary implicit retry.

There is a distinct unresolved causal boundary: a provider can emit a declaration as a completed first ASR and later emit **a refusal or answer modification from the same already-written local input**, with no new positive DSP frame between them. The filter correctly rejects that later non-allowlisted segment and retires the old claim, but a slow/fast SDK schedule may mean the first declaration's formal grade was already committed. No current local waiting marker proves that all semantic intent was received, and cancellation cannot undo a committed formal grade. Example: first segment “当前题，我的答案是WEX指向NUD”, later segment “但是先不要评分” or “改成REZ”. Do not claim the proposed tail route prevents premature grading of those cases; do not silently roll back history either.

Accordingly, the narrow route may repair the **observed pure-request tail** while explicitly retaining general unknown-fragment/refusal continuation as unverified. If complete intent before any formal commit is a requirement, a reliable authoritative whole-input transcription/end signal (or an explicit final user confirmation) is still needed; a local phrase ID, waiting timeout or arbitrary fixed delay cannot prove that boundary. This limitation is separate from the positive-PCM ownership checks, which the proposal can preserve.

No concrete owner-transfer bypass is inherent in the specified same-scope design under all the guards above. Actual code, actual negative tests, deployment and any next model/Native result remain pending; physical output and human experience remain unverified.

### Waiting-marker refinement after Main's actual39 chronology

Main supplied the exact scene39 chronology: first ASR 3817.421, provider response.done 3817.485 clears `driver.waiting` through the actual boundary hook, redundant tail ASR 3818.948 arrives afterward. Requiring waiting to remain non-None at every tail check would therefore reject the real target case. The earlier review's suggested **continuous** waiting requirement was too strong; its valid defect is the missing **first-origin** proof.

A narrower corrected design is acceptable: only the first `_take_study_grade_asr` receipt may capture `sealed_phrase`, and only while its actual waiting tuple/sequence proves complete delivery of that original local input. Later tail checks may allow waiting=None after the provider response terminal, provided that origin was already captured and all original owner, provider, connection, token, scope, Core activation/socket, frames, no-new-pin, driver/report object identity, epoch/current snapshot, full write, original DB IDs, once/deadline/task checks still hold. If waiting is present, it must still match the original sequence. The tail must never create a new origin proof from stale report counts. Response terminal alone is not new local PCM, and neither the origin nor this exception is called a provider utterance identity.

Required revised tests are first-origin waiting=None refusal, non-None foreign waiting refusal, and a positive using actual `note_boundary` to remove waiting while the original tool owner stays current. Main is implementing this refinement and diagnostic exception isolation; implementation/test closure is pending independent review. No additional source/real-run claim is made by this clarification.
