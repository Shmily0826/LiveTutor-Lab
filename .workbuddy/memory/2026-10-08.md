# 2026-10-08

## Base architecture evaluation: N.E.K.O vs LiveTutor — concluded, recommend A

Closed the question left open by the LiveTutor freeze (2026-10-07). Lab repo
`D:\CODE\project\LiveTutor-Lab`, commit `aac02a2`. Read-only throughout: neither
`candidates/N.E.K.O` nor `D:\CODE\project\LiveTutor` was modified.

### Decision

**Option A — keep the LiveTutor base.** OLV frozen to Live2D/VRM rendering,
audio I/O, expression/lip-sync mapping. No new perception, proactive, or brain
logic into OLV. No migration started; no `LiveTutor-Next` created (by design).

### Why not B (N.E.K.O as substrate)

- **Teaching layer 0%.** Not experimental, not abandoned — absent. Verified by
  reading grep matches, not counting them: 146 hits for `exercise` are the English
  verb; `quiz` appears only in prompt strings; `textbook` only in code comments.
  Only "tutorial" in the product is seven-day onboarding.
- **Desktop shell closed.** `N.E.K.O.-PC` → 404. Only distributable is a 213 MB
  NSIS installer; `/S` silent install → rc=1; documented channel is Steam. A
  Win32 control experiment proved the GUI subsystem works, so this is a
  *packaging* limit, not an environment limit.
- **Capture is renderer-bound.** `/api/capture/health` → 503 `no_renderer`. No
  headless operation, and capture cannot be tested without a GUI.
- **No AEC.** Echo handling is `difflib.SequenceMatcher` text similarity. Fine for
  a chat avatar, a correctness problem for a tutor that interrupts itself.

Adoption would not reduce teaching work — it would relocate it onto a substrate
that cannot be audited or fixed locally. The 30 % vs 55 % coverage framing is the
wrong comparison; both roads require writing the teaching layer.

### The one positive result worth keeping

**External Brain attachment works without forking — proven live.** A
`ThreadingHTTPServer` registered two custom tools via `POST /api/tools/register`
(per-tool flat schema: `name` + `callback_url`), they appeared in the agent role
(`affected_roles: ["YUI"]`, `source=livetutor_brain`, `is_remote=true`), callback
URLs are loopback-enforced (public host and 169.254.169.254 both rejected 422),
and unregister returns the tool list exactly to baseline.

But the extension point is **tools, not the brain**. N.E.K.O's agent loop is
in-process and owns the turn. Restoring Brain as the brain means replacing that
loop = a fork. The no-fork property holds only at the tool layer, which is not
where LiveTutor's value is.

### Reusable technical findings

- **asar parsing traps**: header JSON size field includes padding (use
  `raw_decode`, base = `16 + json_size`); file paths have **no** leading `/`
  (else 0 files extracted); `offset` is a string.
- **N.E.K.O storage gate**: only `POST /api/storage/location/restart` with the
  root in the body commits. Env var and `/select` both fail — a force kill reverts
  `last_migration_result` to `launcher_phase0_bootstrap`.
- **Windows self-window exclusion**: N.E.K.O's Electron shell does it correctly
  (enumerate → hide all → wait for compositor 90 ms/350 ms Wayland → capture →
  restore in `finally`) but that shell is closed source. The right Windows
  primitive is `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`, which **no
  candidate project uses**.
- **Backend lifetime**: dying when the launching shell exits
  (`502 upstream connect failed`) is already documented in
  `LiveTutor/docs/v0.2-final-acceptance.md:65-69`. Same trap, two projects.
- **Environment constraints**: PowerShell and `cmd.exe` from the Bash tool are
  both policy-blocked — route shell work through Python.

### Prior asset confirmed, not a new finding

The v0.3 spike already adopted Skilly's DOM digest grounding
(`LiveTutor/spikes/v0.3-structured-context/web_context.py`). Base-independent, so
it survives any base decision.

### What would flip the recommendation

N.E.K.O opening the shell source *and* moving capture out of the renderer; or
N.E.K.O shipping any teaching-layer work at all (re-check §5 first — that single
fact flips it); or a third party shipping a Windows tutor substrate with
`WDA_EXCLUDEFROMCAPTURE` done properly.

### Honest gaps

Desktop shell, avatar, voice path, barge-in, proactive speech and dialogue quality
(5–8 turns) were **BLOCKED in actual use**, not verified. This machine's loopback
is silent, so audio claims are unverifiable here for LiveTutor too.
